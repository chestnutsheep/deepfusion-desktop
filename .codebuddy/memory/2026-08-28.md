# 2026-08-28

## Bug 修复：面板关不掉 / 关闭后自启
**根因（两层保活）**：
1. systemd 用户服务 `deepfusion-desktop.service` 配 `Restart=always` → 面板退出即拉起。
2. `start-desktop.sh` 内含 `while true` 守护循环 → 面板进程退出 3s 后自动重启。
用户杀面板后它又起来，无法做别的事。

**解决方案（后端生命周期改由 Tauri 接管）**：
- 禁用 systemd 自启：`systemctl --user disable deepfusion-desktop.service`。
- 重写 `start-desktop.sh`：`cleanup_old` + 一次性起 5173 后端后退出，去掉 `while true`。
- `src-tauri/src/lib.rs` 新增 `start_backend`（`Command::new("bash").process_group(0)` spawn `uv run serve.py`，pgid==pid）、`stop_backend`（`libc::killpg(pgid, SIGKILL)` 整组清除）、`backend_status`；Cargo.toml 加 `libc`。
- `dashboard/src/main.jsx`：加载时 `invoke('start_backend')` 自动起后端；"关闭主屏"→`stop_backend`+`hide()`+显示"启动应用"覆盖层；新增覆盖层 `app-launcher` 点"启动应用"→`start_backend`+`show()`。样式见 styles.css 新增 `.app-launcher`/`.launch-button`。

**验证**：运行新二进制→5173=200、后端 pgid==pid；`kill -9 -<pgid>` 整组清除→5173 断开。systemd 已 disabled，无残留进程。

**注意**：`cargo build --release` 可绕过 tauri CLI 的 inotify "OS file watch limit" 报错（环境 inotify 实例上限问题），产物在 `target/release/deepfusion-desktop`。完整 `tauri build` 仍受 watcher 限制。
