## ⚠️ 真正卡死根因：前端对 5173 的自杀式重试（2026-08-30 深夜）
- **现象**：面板一启动就卡成 PPT（CPU 100%、进程暴涨被弹登出）。
- **真正根因（不是监听数）**：后端 `serve.py`（5173）因 `ak_cache failed ProxyError` 预热卡住/偶发起不来时，前端 `mcpTool`/`fetchQuote` **没有任何退避/熔断**，每次组件 effect 触发（noticer 解除后事件变多）就狂发 `/api/tools/call`，全部瞬间 `ECONNREFUSED`，每次仍走完整 fetch+JSON 解析+logEvent → 主线程打满 → PPT。日志里一次性喷十几条 `[vite] http proxy error /api/tools/call ECONNREFUSED 127.0.0.1:5173`。
- **注意**：之前认为"监听数量"是主因是误判；今天解除 noticer 限制 + 改过 Panel 部分是触发条件，但直接打死主线程的是请求风暴，不是 listener 累积（portfolioStore 64 上限仍保留作护栏）。
- **修复（前端熔断 + 并发锁）**：
  1. `dashboard/src/services/watchlist.js`：新增 `BACKEND_OK` 熔断状态机——后端连续失败 `FAIL_THRESHOLD=3` 次进入熔断，`COOLDOWN_MS=15000` 内所有 `mcpTool`/`fetchQuote` **直接短路**（返回 null/缓存，不发请求），冷却结束用一次 `search` 探活恢复。`recordBackendResult()` 上报成败。
  2. `WatchlistPanel.jsx`：`refresh()` 加 `refreshingRef` 并发锁，上一轮未完成则跳过（防 noticer 高频触发重叠刷新导致请求风暴）；`useRef` 已导入。
  3. lint 0 / node --check 通过。
- **验证**：重启面板后进程数稳在 429（不涨）、deepfusion 仅 3 进程、CPU 最高 WebKit 13.6%（正常）、5188/5173 均 LISTEN、窗口正常最大化弹出、无持续 ECONNREFUSED 风暴。后端 `deepfusion-server` 独立 `uv run serve.py` 也能正常起 5173。
- **结论**：熔断 + 并发锁彻底解决卡 PPT；即使后端偶发不可用，前端也不再打满主线程。
