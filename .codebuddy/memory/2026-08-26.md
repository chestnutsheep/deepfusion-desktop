### BUG2 背景（油画层）消失 —— 真根因（8-27 用 playwright 实测突破）
- **之前所有分析（环境/缓存/GNOME/变量脆弱性/那个 Agent 误建 vite.config）都错。** 那个 Agent 在 DeepFusion memory 里自称"已修复油画层"是假的——用户明确说"他没修好"，因为他弄混两个 build、且路径本身有 bug。
- **真正 bug**：`main.jsx` 把 `--theme-image: url(./assets/${file})` 注入 `<main>` 的 style，油画图在 `styles.css` 的 `.desktop::before` 用 `var(--theme-image)` 引用。**CSS 规范陷阱：`var()` 里的 `url(./assets/x)` 相对基准是"使用该变量的 CSS 文件位置"（`dist/assets/index-*.css`），不是文档**。于是 `::before` 解析后变成 `url(assets/assets/matin.JPEG)`（多一层 assets）→ 在 Tauri `asset://` 协议下 404 → 油画图永不显示 → 油画层消失。这正是"他没修好"的真相。
- **实证**：playwright 探针（chromium 截图 + computed style）显示修复前 `::before` backgroundImage 第三层 = `url(http://localhost:4173/assets/assets/matin.JPEG)`（双层 assets，错）；修复后 = `url(http://localhost:4173/assets/matin.JPEG)`（单层，对）。
- **修复**：`main.jsx:358` 改为 `--theme-image: url(/assets/${theme.file})`（**绝对路径**，不受 CSS 文件基准影响，永远指向根 `/assets/`）。已 `npm run build` + playwright 验证通过。
- **教训（重要）**：Tauri/Vite 项目中，**不要把图片 URL 放进 CSS 变量再用 `var()` 在 `::before` 等伪元素引用相对路径**——相对基准会变成 CSS 文件目录，导致双路径 404。要么用绝对路径 `/assets/`，要么把图片直接内联到 DOM 元素 style（基准是文档）。
